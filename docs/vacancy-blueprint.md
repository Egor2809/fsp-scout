# Бланк теста вакансии

GET /api/v1/vacancies/:id/test-blueprint реализован в исходниках.
Применяются правила видимости самой вакансии: черновик доступен владельцу,
опубликованная вакансия — кандидату и работодателю; закрытая также доступна
кандидату, уже подавшему отклик. Подмена UUID не обходит проверку компании.

Бланк строится из сохранённых must/nice-навыков вакансии. Обязательный навык
имеет вес 2, желательный — 1, веса нормируются. Навыки сопоставляются с
явными skillIds семейств текущего банка в специализации вакансии. Когда
один навык покрывает несколько компетенций, его вес делится между ними.
Количество семейств считается по уникальным ID. Непокрытый навык сохраняет
свой вес и отдельную компетенцию skill:<id> с families_count=0.
При пустом наборе навыков используются реальные компетенции специализации
с равными долями. Это не оценка качества или достаточности банка.

Практика пока null; min/max берутся из текущей политики CAT. Ответ — план,
а не разрешение начать тест. Start с vacancy_id пока отклоняется, поскольку
ещё нужны сохранённая версия бланка, достаточный банк, взвешенный отбор,
практический блок и проверка полного жизненного цикла.

Проходят 52 модульных теста, включая веса, реальные счётчики и пробелы покрытия.
Интеграционный сценарий вакансии дополнен проверками видимости бланка;
HTTP-сценарий запускается через `npm run test:integration`.
