# Состояние сессии тестирования

Реализованы GET /me/tests, GET /tests/:id, GET /me/grade-history и POST /tests/:id/answers.
Выборка ограничена кандидатом из проверенного JWT. Ответы и ключи не включаются в
проекцию сессии или историю тестов. Просроченные сессии синхронизируются при чтении.

Сессия хранит собственную policy, bankVersion и связь с вакансией. Политика содержит
min/max, SE, topK, экспозицию и число практических заданий. Миграционный default
practiceTotal=0 не является утверждением о готовом практическом блоке: полноценная
практика и команда finish ещё не реализованы. Start и next реализованы в исходниках,
но start закрыт проверкой недостаточного банка; успешный HTTP-сценарий не проверен.

Выданное задание хранит ordinal, competency, block, issuedAt, закрытый ключ ответа,
ответ и телеметрию. Уникальные индексы запрещают повтор семейства, повтор ordinal
и два неотвеченных задания в одной сессии. Миграция откажется применяться к старой
сессии с несколькими неотвеченными заданиями, вместо удаления её данных.

POST answers блокирует Candidate, затем TestSession. Принимается только текущее
задание своей сессии. Повтор того же принятого ответа идемпотентен, изменение
ответа возвращает конфликт. Порядок выбранных вариантов не меняет идентичность
ответа; rt_ms и счётчики событий не входят в ключ повтора и не перезаписываются.
Граница срока включительна; истечение фиксируется до возврата ошибки.
Правильность и expectedAnswer в AnswerAck не раскрываются.

Сохраняются client_rt_ms, server_elapsed_ms, paste_count и focus_lost_count.
Они не являются основанием для автоматического провала. Модель времени ответа,
вычисление флагов и финальный результат ещё предстоят. Pending кодовых/открытых
ответов пока отклоняется: реальный sandbox/review ещё не подключён.

GradeHistory отделён от изменяемого JSON профиля. testId уникален, чтобы один тест
не создавал две смены категории. Запись истории вместе с обновлением категории
будет частью транзакции finish; сейчас доступно только чтение истории.

## Экспозиция

Helper exposure использует реальное число начатых сессий соответствующего банка
и специализации за 90 дней. Выдача допускается только при served + 1 <= floor(N * 0.2).
Фиктивных bootstrap-наблюдений нет: при N < 5 выдача невозможна.
Next применяет этот фильтр под advisory-блокировкой банка и специализации;
срок повторно проверяется после ожидания блокировки и перед сохранением выдачи.
Транзакционную корректность на PostgreSQL ещё нужно проверить интеграционно.
Если обязательная компетенция недоступна, CAT не заменяет её посторонним заданием
и не объявляет успешное завершение.

## Проверки и ограничения

Чистые тесты проверяют прогресс, различие минимальной длины и остановки CAT,
повторы ответа, единичное текущее задание, строгий порог экспозиции и недоступность
обязательной компетенции.
Полная сессия (старт, ответы, практика в Piston, завершение и результат)
проверена на развёрнутом стенде.
