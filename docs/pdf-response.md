# Передача PDF по API

ContractResponseInterceptor распознаёт NestJS StreamableFile с type application/pdf и пропускает файл только при объявленном для текущего статуса PDF-ответе. Строка или произвольный объект с заголовком application/pdf не принимаются; StreamableFile не проходит через JSON/Zod. Также отвергается пустой ответ там, где контракт требует содержимое, и содержимое при статусе 204.

Добавлен исходный генератор scripts/render-profile.py: JSON из stdin, PDF в stdout без промежуточных файлов с персональными данными. Использует ReportLab 5.0.1, DejaVu Sans, переносимые абзацы и QR-ссылку. В Docker добавлены шрифт, зависимость и скрипт. Отображает подтверждённую категорию, процентиль, ФСП-счётчик, контакты, описание, навыки с разделением подтверждённых/заявленных и опыт. Вход ограничен 200000 байт, выход 5 MiB, сообщения ошибок не содержат профиль или токен. Для локальной Windows нужен PROFILE_PDF_FONT с путём к кириллическому TTF.

Добавлен Node helper renderProfilePdf: максимум два процесса, тайм-аут 10 секунд, предел вывода 5 MiB, проверка PDF-сигнатуры. Permit освобождается на close, после фактической остановки процесса; ошибки не содержат PII. verificationUrl принимает явный публичный API base без credentials/query/hash и непрозрачный токен; QR пока ведёт на JSON verify API, отдельная публичная HTML-страница не реализована.

Обновление: добавлена публичная frontend-страница /verify/:token, без входа, с категорией/процентилем/датами и состояниями 404/сбоя. PUBLIC_VERIFICATION_BASE_URL задаёт её origin (локально http://localhost:5173); при отсутствии используется прежний PUBLIC_API_URL. Запрос не получает токен текущей пользовательской сессии, browser cache отключён, query cache удаляется после ухода; проверка повторяется при фокусе и раз в 30 секунд. Во время повторной проверки или ошибки прежние claims не отображаются.

Подключён GET /api/v1/me/profile.pdf с AuthGuard candidate. Требуются подтверждённая standing, personal_data consent и состояние, отличное от not_looking. PUBLIC_API_URL задаёт доступный получателю адрес API (локально localhost подходит только для того же компьютера). Генерация вне транзакции; перед сохранением token hash и claims профиль, privacy, набор согласий и ФСП-счётчик повторно сверяются под блокировкой Candidate. Изменение или отзыв/повторное согласие во время генерации отклоняет выдачу. Audit содержит только факт выдачи; ответы no-store, attachment, nosniff.

Синтаксис Python проверен через ast.parse. 78 модульных тестов проходят, включая построение ссылки; это не тест реального генератора. ReportLab и шрифт ставятся при сборке Docker-образа API. Проверка исходников не заменяет загрузку реального файла: необходимы HTTP-тест с Content-Disposition, проверка PDF-парсером, визуальный просмотр и чтение QR.
