# Внешняя оценка ранжирования

В исходниках добавлен POST /api/v1/eval/rank для employer/admin. Вход и JSON-выход
соответствуют сохранённым схемам контракта; HTTP и сборка ещё не проверены.
Accept: text/csv включает CSV с экранированием кавычек и защитой формульных ячеек.
Повторяющиеся ID и неверные зарплатные диапазоны отклоняются.

Алгоритм использует словарь навыков и BM25. Вклад в 100-балльную оценку:
покрытие навыков 60, лексическая релевантность 25, зарплата и формат 10,
отрасль 2.5, заявленный грейд 2.5. Обязательные навыки имеют двойной вес.
Неизвестные условия дают половину соответствующего вклада. Эта оценка не
содержит подтверждённых тестовых результатов или FSP: внешнее резюме их не доказывает.
Для JSON Resume имя, контакты, адрес и ссылки не участвуют в ранжировании.
Для обычного текста структурного исключения контактных полей пока нет.

Чистая функция rankingMetrics рассчитывает NDCG@k, Recall@k и reciprocal rank@k
по независимым оценкам релевантности 0..4. Для MRR нужно усреднить reciprocal rank
по запросам. Неразмеченные кандидаты считаются нерелевантными; качество зависит
от полноты разметки. При отсутствии релевантных документов возвращаются нули.
Дубликаты в ранжировании и некорректные метки отклоняются.

47 модульных тестов проходят, включая четыре проверки внешнего ранжирования,
CSV и метрик. Это проверка поведения кода, а не измерение качества поиска.
Нужны независимый размеченный набор, сравнение с базовыми алгоритмами,
проверка производительности на предельном размере входа и HTTP-интеграция.
