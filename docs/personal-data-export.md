# Экспорт персональных данных

GET /api/v1/me/export реализован в исходниках для candidate/employer.
Выбор пользователя выполняется только по subject проверенного JWT; параметры
запроса не позволяют выбрать чужой аккаунт. Ответ — JSON-вложение с Cache-Control: no-store.
Все чтения выполняются в одной RepeatableRead-транзакции.

Выгружаются учётная запись и членство в компаниях. Для кандидата также включены
профиль, приватность, согласия, опросы, история категорий, привязка FSP,
раскрытия контактов, тестовые сессии и собственные ответы/телеметрия,
приглашения, отклики, назначения заданий и собственные решения с оценками.
Закрытые ключи и параметры генерации тестовых заданий, внутренние события
работодателей, профили других кандидатов и реестр участников FSP не выгружаются.

Экспорт не заменяет удаление аккаунта. Полный процесс удаления, политика
хранения журнала аудита и выгрузка относящихся к субъекту записей аудита ещё
предстоят. Для большой истории нужен потоковый экспорт или фоновый артефакт:
текущий вариант собирает ответ в памяти. Это ограничение нужно измерить нагрузочно.

Подготовлен integration/export.test.mjs: проверяет авторизацию, собственный
subject, заголовки и отсутствие ключей заданий. Нужны работающий API,
TEST_CANDIDATE_TOKEN и TEST_EMPLOYER_TOKEN. Тест пока не выполнялся;
проверка синтаксиса Node не подтверждает поведение HTTP или Prisma.
