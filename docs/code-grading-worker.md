# Скрытая оценка практики

Ответ с кодом проходит структурную проверку и сохраняется с correct=null.
В той же транзакции создаётся Outbox assessment.code_submitted, содержащий
только itemId/sessionId/candidateId. Повтор такого же ответа возвращает Ack,
другой ответ конфликтует; второй event не создаётся. Скрытые входы/ответы и код
не попадают в BullMQ payload или журналы.

Worker имеет отдельную очередь assessment-grading и планировщик каждые 5 секунд.
Одна задача забирает один Outbox через FOR UPDATE SKIP LOCKED, получает случайный
claimToken и lease 180 секунд. Транзакция завершается до обращения к Piston.
Код, точный runtime и все серверные тесты читаются из БД. Для новой политики
добавляется десятая проба уточняющего вопроса. Успех требует
status=ok и прохождения всех случаев; ошибка компиляции/выполнения — неправильный
ответ, недоступность исполнителя — техническая ошибка с повтором.

Перед записью worker блокирует Candidate → TestSession → Outbox и проверяет
claimToken/lease, срок, активность, согласие и correct=null. Истёкший или чужой
lease не может записать результат. Повторная доставка не меняет уже оценённый
ответ. При успехе практики здесь же создаётся вопрос блока C (docs/assessment-approach.md).
Отозванное согласие/завершённая сессия не получают позднюю оценку.
Просроченная сессия синхронизируется в expired. В аудит пишутся только ID,
правильность и версия runtime.

Ошибки повторяются с задержкой 5/10/20/40 секунд, максимум 5 попыток.
После исчерпания event получает failedAt; correct остаётся null, ошибка не
становится автоматическим провалом кандидата. Потерянный lease последней
попытки также переводится в failedAt. Восстановление dead-letter требует
операторской процедуры, которая ещё не реализована. Полный мониторинг и
повтор без потери сессии после длительного сбоя ещё нужно спроектировать.

Next при ожидании возвращает контрактный Problem conflict с расширениями
assessment_state=grading_pending и retry_after_sec=2. TestRun показывает
«Ответ принят. Проверяем решение» и опрашивает next до двух минут, затем
остаётся ручная проверка готовности. Для dead-letter возвращается явная
техническая ошибка grading_failed. Сами правильность и скрытые случаи до
завершения не раскрываются.

Добавлена миграция 20261010009000_outbox_leases.
Worker получает PISTON_EXECUTE_URL через Compose; runtime закреплён в сессии.
69 модульных тестов проходят, включая правила повторов и fencing. Это не
проверка SQL/Redis/Piston: нужны реальные интеграционные тесты потери worker,
истечения lease, duplicate delivery, задержек, отзыва согласия и смены срока.
