# Запуск открытых тестов

POST /tests/:id/run добавлен в исходниках. Доступен кандидату для своего
активного неотвеченного кодового задания, при согласии personal_data.
Язык должен совпадать с answer_language. Открытые тесты берутся из сохранённого
publicItem, не из запроса пользователя. Ответы/профиль кандидата в песочницу
не передаются. Код отправляется только настроенному оператором исполнителю.

Клиент реализован по официальному API Piston:
https://github.com/engineer-man/piston/blob/master/docs/api-v2.md
Настройки: PISTON_EXECUTE_URL (полный URL /api/v2/execute),
PISTON_PYTHON_VERSION, PISTON_GO_VERSION, PISTON_JAVASCRIPT_VERSION.
Версия обязательна в точном виде X.Y.Z; wildcard не допускается. Язык/версия
ответа проверяются. Redirect запрещён. SQL/Java/TypeScript/YAML/text пока
не подключены; возвращается конфликт, а не выдуманный результат запуска.

Каждый открытый тест запускается отдельным запросом со stdin. Сравнивается
реальный stdout с expected, нормализуются CRLF и конечные пробелы. Нулевой код
выхода сам по себе не подтверждает правильность. compile_error/runtime_error/
timeout различаются; неисполненные случаи не становятся успешными.
Ограничения клиента: 10 случаев, 20000 символов кода/входа/expected,
64 КиБ ответа исполнителя, 8000 символов stdout/stderr на случай,
compile_timeout=10000, run_timeout=3000, память компиляции 256 МиБ,
выполнения 128 МиБ. Ошибка связи не выдаётся за неправильный ответ кандидата.

Резервирование запуска выполняется под блокировкой кандидата/сессии и пишется
в аудит без кода. Лимит: 3 запуска за скользящую минуту, 20 за сессию,
включая неуспешное обращение к исполнителю. Два запроса-решения одновременно
на экземпляр API. Это клиентский предел: сервер Piston должен независимо
ограничивать задания, особенно если запрос прерван по дедлайну до завершения
серверного процесса. После получения ответа API повторно проверяет активность сессии.

Песочница пока не развёрнута и не добавлена автоматически в Compose.
Нужны отдельный изолированный узел, установленные закреплённые runtimes,
ограничение сети пользовательского процесса, памяти/CPU/PID/вывода и проверка
устойчивости к зависанию, fork/memory/output bomb. API не выполняет код локально.
Тайм-ауты в HTTP-клиенте не доказывают изоляцию исполнителя.

62 модульных теста проходят. Протокол проверяется подставным транспортом,
реальный код не запускается этими тестами. Нужны настоящие HTTP/e2e проверки,
генерация практики, скрытые тесты при ответе и уточняющий вопрос блока C.
Результат /run не сохраняется как правильность и не меняет CAT/грейд.
