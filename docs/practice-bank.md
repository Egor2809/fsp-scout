# Практический банк

Добавлены пять параметризованных семейств practice-20261010-v1:
максимальная сумма фиксированного окна, сумма последних значений по ключам,
длина объединения полуоткрытых интервалов, максимальная непрерывная серия,
максимальная параллельность интервалов. Это кодовые задачи для backend,
frontend и mobile; кейсы QA/DevOps/аналитиков/Data ML ещё нужно подготовить.

Протокол: JSON из stdin, одно целое число в stdout. Генератор создаёт два
открытых примера и семь дополнительных закрытых случаев. Серверная проверка
в expectedAnswer содержит все девять случаев, включая открытые. Наборы
проверяют пустой вход, короткий вход, отрицательные значения, замены по ключам,
пустые/соприкасающиеся/пересекающиеся интервалы и разрыв серии.

В publicItem входят только открытые примеры и условие; seed, parameters и
expectedAnswer туда не включаются. Заготовки предусмотрены для Python,
JavaScript и Go. Семейства не объявлены эмпирически откалиброванными:
discrimination/difficulty здесь предварительные технические значения.
Объединять практическую правильность с IRT-шкалой без проверки калибровки нельзя.

Модульные тесты перебирают 100 seed на семейство (500 вариантов), сравнивая
ответы с независимыми алгоритмами: прямой перебор окон, поиск последних
записей, целочисленное покрытие интервалов и перебор стартов серии.
Всего проходят 67 модульных тестов. Код кандидата этими тестами не исполняется.

Генератор подключён к start/next в исходниках. Новая политика требует одну
практическую задачу, сохраняет practiceBankVersion/familyIds/language/runtimeVersion.
Frontend-специализация использует JavaScript, backend/mobile — Python.
При отсутствии подходящего банка или настроенной песочницы start отклоняется.
Next после остановки CAT выбирает неповторённое наименее использованное семейство
с доступной перспективной ёмкостью экспозиции <=20%; при равенстве применяется
seeded random. Практическая когорта включает только сессии той же версии практики.
Выдача находится под той же advisory-блокировкой банка/специализации.
Повтор next возвращает сохранённый publicItem. Pending-оценка блокирует продвижение.
Версия runtime для /run берётся из сессии, а не из изменившегося окружения.

Провал или пропуск обязательной практики не подтверждает новую категорию даже
при сильном CAT. Практическая правильность пока не добавляется к IRT как будто
имеет измеренные параметры. Старые сессии без практики не подтверждают новый грейд.
Worker скрытой оценки подключён в исходниках (docs/code-grading-worker.md),
но реальная цепочка ещё не проверена. Нужны
развёрнутый Piston, атомарная обработка pending-ответов, ограничения входа,
проверки больших массивов/эффективности и уточняющий блок C. Наличие генератора
ещё не делает полный практический сценарий работающим.
