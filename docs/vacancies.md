# Вакансии и отклики

Реализованы создание и обновление вакансии, список компании, опубликованная выдача
с фильтрами и пагинацией, чтение, отклик, списки откликов и смена статуса.
Черновик доступен владельцу. Закрытая вакансия остаётся доступна кандидату,
который уже откликнулся, для просмотра истории.

Отклик разрешён после согласия personal_data и является явным раскрытием контактов
компании вакансии. Согласие на публикацию анонимной карточки для этого не требуется.
Раскрытие записывается отдельно с компанией, причиной, источником и аудитом.
Отзыв отклика прекращает процесс найма, но не отменяет уже состоявшееся раскрытие.
Другие компании не получают доступ к отклику или контактам через эти маршруты.

Один отклик на пару вакансия/кандидат защищён уникальным индексом. Отзыв не позволяет
создать дубликат. При отклике используются блокировки Company -> Candidate -> Vacancy;
закрытие вакансии сериализуется той же блокировкой Vacancy. При смене статуса
блокируется Application и проверяются роль, владелец и переход.

Этапы: submitted -> viewed/interview/rejected; viewed -> interview/rejected;
interview -> offer/rejected; offer -> hired/rejected. Кандидат может отозвать
активный отклик. hired/rejected/withdrawn являются конечными состояниями.

Приглашение может ссылаться на опубликованную вакансию своей компании. При source
типа vacancy его ID должен совпадать с vacancy_id, если переданы оба поля.
В карточке кандидата показывается последний отклик в текущую компанию.

## Проверка

Чистый тест application-state.test.ts проверяет права и переходы. Для HTTP:

    cd backend
    npm run test:integration

Нужны TEST_API_URL (по умолчанию http://localhost:8000/api/v1), TEST_CANDIDATE_TOKEN,
TEST_EMPLOYER_TOKEN и TEST_OTHER_EMPLOYER_TOKEN. Это действующие JWT Keycloak:
кандидат и два работодателя разных компаний. Компании назначаются операторским CLI.
Использовать отдельную локальную БД и тестовые аккаунты. Сценарий выдаёт согласие
кандидата, создаёт вакансию и отклик, затем закрывает вакансию; история остаётся в БД.
Токены и контакты не выводятся в журнал.

Сценарий проверяет ownership, гонку дублирующих откликов, раскрытие только владельцу,
ролевые запреты и конечное состояние после отзыва. На текущей среде он не запускался.
Миграция 20261010005000_vacancies также ещё не проверена на PostgreSQL.
Test-blueprint вакансии остаётся частью модуля реального банка и тестирования.
