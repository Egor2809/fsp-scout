# Восстановление технически неоценённого ответа

После устранения причины отказа Piston оператор с доступом к базе может повторно поставить конкретное dead-letter событие:

```powershell
cd backend
npm run assessment:retry -- <UUID-события-Outbox> "Причина и номер инцидента"
```

Команда использует DATABASE_URL и требует установленных зависимостей backend. Предназначена для административного окружения, не является публичным API. Она не вызывает Piston сама: оценку подбирает работающий grading worker.

Повтор разрешён только для failed, недоставленного события assessment.code_submitted без действующей аренды, связанного с ещё активной попыткой, действующим согласием и отправленным, но неоценённым ответом. Под блокировками Candidate → TestSession → Outbox очищаются ошибка, lease и счётчик попыток. Причина, прежняя ошибка и число попыток записываются в Audit. Код и ответы в журнал не копируются. Повтор команды после успешной постановки отклоняется.

Срок теста не продлевается, correct не меняется. Просроченные попытки и уже оценённые ответы команда не восстанавливает. До запуска проверьте доступность песочницы и конфигурацию runtime.

Подготовлен `backend/integration/grading-recovery.test.mjs`: создаёт собственные fixtures, проверяет два конкурентных retry, неизменность ответа, аудит и отказ при действующем lease или истёкшем сроке. Для запуска нужны мигрированная выделенная тестовая БД, зависимости и `TEST_DATABASE_ISOLATED=1`; grading worker на время этого сценария должен быть остановлен. Запуск: `node --test integration/grading-recovery.test.mjs` из backend. Синтаксис сценария проверен; реальный PostgreSQL-прогон пока не выполнен. Конкуренция именно с работающим worker требует отдельного сценария.
