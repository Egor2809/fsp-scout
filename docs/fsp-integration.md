# Интеграция с реестром ФСП

Реальный API ФСП организаторы не предоставили. В прототипе работает локальный реестр участников
с тем же контрактом, что предлагается для боевой интеграции: привязка ФСП ID к профилю, подписанные
события о достижениях и их учёт в подборе. Демонстрационные достижения синтетические и так помечены.

## Схема

```
 Реестр ФСП                         Скаут                                   Кандидат
 ──────────                         ─────                                   ────────
                                                                  согласие fsp_data
                                                                  ФСП ID в разделе «ФСП»
                                    POST /api/v1/me/fsp/link  ◄────────────┘
                                    1. есть согласие fsp_data?
                                    2. участник найден и ownerSubject = sub токена Keycloak?
                                    3. ФСП ID ещё не привязан к другому профилю?
                                    → FspLink: профиль ↔ участник реестра

 событие achievement.created
 X-FSP-Signature: HMAC-SHA256 ────► POST /api/v1/webhooks/fsp
 исходного тела                     4. подпись проверяется до записи данных
                                    5. срок: не старше суток, не дальше 5 минут в будущем
                                    6. хеш тела в WebhookReceipt: повтор не создаёт дубль,
                                       тот же id с другим содержимым отклоняется
                                    7. достижение и профиль меняются одной транзакцией

                                    Подбор: бонус ФСП 0–15 к силе профиля, только по
                                    проверенным достижениям и при действующем согласии;
                                    в объяснении выдачи отдельный фактор
                                    «Подтверждённые достижения ФСП»
```

## Что учитывается

- **Без истории ФСП нет штрафа.** Индекс и бонус равны 0, кандидат ранжируется по тесту и навыкам,
  в карточке пометка «Нет истории ФСП».
- **Грейд ФСП не меняет.** Категорию подтверждает только тест; достижения поднимают кандидата
  внутри категории.
- **Согласие отзывается.** Отзыв `fsp_data` удаляет связь и копию достижений из профиля.
- **Владение доказывается, а не заявляется.** Ввести чужой ФСП ID нельзя: привязка проходит только
  при совпадении владельца участника с проверенным `sub` OIDC-токена.

## Сейчас в прототипе

Владельца участника и его достижения задаёт оператор через CLI с доступом к БД
(`achievements.json` — массив достижений по схеме API; без файла создаётся участник без истории):

```bash
node --env-file=.env --import tsx scripts/provision-fsp.ts --subject KEYCLOAK_USER_UUID --fsp-id FSP-77-000001 --achievements achievements.json
```

Вебхук `POST /api/v1/webhooks/fsp` принимает `achievement.created`. Подпись — hex HMAC-SHA256
  исходных байтов тела с секретом `FSP_WEBHOOK_SECRET` (не короче 32 символов), допускается префикс
  `sha256=`. Секрет подписи не даёт права создавать владельцев участников.

## Что нужно от ФСП для боевой интеграции

1. **ФСП ID как провайдер входа в Keycloak.** Привязка по клиентскому account linking
   (`kc_action=idp_link`) уже заложена во фронтенде; операторский шаг CLI заменяется доказательством
   владения от доверенного IdP ФСП.
2. **Поток событий реестра.** Отправка `achievement.created` на вебхук с общим секретом; при
   необходимости — одноразовая серверная сверка участника, привязанная к сессии пользователя.
3. **Согласованный формат.** Транспорт, ключи, схема достижения и правила исправления протоколов
   задним числом согласуются с Федерацией после хакатона.
