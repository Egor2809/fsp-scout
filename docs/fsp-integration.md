# Интеграция ФСП

Реального API ФСП организаторы не предоставляют. Сейчас реализован
локальный тестовый реестр FspParticipant, а не предполагаемое внешнее API.
Достижения и их владельца задаёт оператор через CLI с доступом к БД.

```powershell
node --env-file=.env --import tsx scripts/provision-fsp.ts --subject KEYCLOAK_USER_UUID --fsp-id FSP-77-000001 --achievements achievements.json
```

JSON содержит массив достижений по схеме API. Отсутствие файла означает
участника без истории. Только совпадение ownerSubject с проверенным sub
OIDC-токена позволяет привязку. Для реальной интеграции этот операторский
шаг заменяется доказательством владения от доверенного ФСП IdP или
одноразовой серверной проверкой реестра, привязанной к сессии пользователя.

Привязка требует согласия fsp_data. Отзыв согласия удаляет связь и копию
достижений из профиля. Без истории index=0 и bonus=0; отдельного штрафа нет.

Вебхук принимает achievement.created. X-FSP-Signature — hex HMAC-SHA256
исходных байтов JSON-тела с FSP_WEBHOOK_SECRET (не менее 32 символов).
Допускается префикс sha256=. Событие доставляется в пределах суток,
допустимое отклонение времени в будущее — 5 минут.

Hash исходного тела записывается в WebhookReceipt. Повторная доставка не
создаёт второе достижение. Повтор achievement.created с другим содержимым
того же achievement.id отклоняется. Изменения реестра и связанного профиля
происходят в одной транзакции; подпись проверяется до записи данных.

Транспорт, ключи и формат будущего реестра согласуются с ФСП после хакатона.
Секрет подписи не даёт права создавать владельцев участников через webhook.
Операторские демонстрационные данные должны явно обозначаться синтетическими.
