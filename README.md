# Скаут × ФСП — обратный найм в ИТ

Кандидат проходит адаптивный тест и получает подтверждённую категорию «специализация · грейд» с перцентилем.
Работодатель ищет по подтверждённым категориям, видит объяснение ранжирования и приглашает с обязательной вилкой.
Контакты кандидата открываются только после принятия инвайта.

## Запуск одной командой

Нужен Docker с Compose v2. Порты 5432, 6379, 8000, 8025, 8080 и 8081 должны быть свободны.

```bash
cd infra
cp .env.example .env
docker compose up --build
```

Первый запуск занимает несколько минут. Когда в логах появится `web` и `api` станет healthy, откройте:

| Что | Адрес |
|---|---|
| Приложение | http://localhost:8081 |
| Keycloak (admin / admin12345) | http://localhost:8080 |
| Почта регистрации (Mailpit) | http://localhost:8025 |
| API | http://localhost:8081/api/v1 (напрямую: http://localhost:8000/api/v1) |

Если порт 5432 занят локальным PostgreSQL, задайте в `.env` `POSTGRES_HOST_PORT=5433`.

## Демо-учётки

Пароль у всех: `demo12345`. На странице входа есть кнопки быстрого входа, email подставляется сам.

| Роль | Email | Что внутри |
|---|---|---|
| Кандидат | candidate@demo.ru | Пустая учётка: согласия, опрос, тест проходятся с нуля |
| Работодатель | employer@demo.ru | Компания «Северный код», 2 потребности, 2 подборки, вакансии |
| Администратор | admin@demo.ru | Роль admin для API |
| Жюри 1–5, кандидат | jury1-candidate@demo.ru … jury5-candidate@demo.ru | Отдельная чистая учётка кандидата |
| Жюри 1–5, работодатель | jury1-employer@demo.ru … jury5-employer@demo.ru | Своя компания без инвайтов |

Сервис `seed` после миграций идемпотентно наполняет базу: 420 синтетических кандидатов
(7 специализаций × 4 грейда), у всех подтверждённая категория, навыки и согласие на показ,
у четверти есть достижения ФСП; вакансии нескольких компаний.

## Сценарий проверки

1. Войти как `juryN-candidate@demo.ru`: согласия → опрос → тест → результат с категорией и перцентилем.
2. Войти как `juryN-employer@demo.ru` (лучше в другом браузере или инкогнито): «Новая потребность» или «Банк кандидатов» → карточка → инвайт с вилкой.
3. Снова кандидатом: «Инвайты» → принять. Работодатель видит контакты в карточке кандидата.

## Валидация

`cd backend && npm run eval` прогоняет боевой тест и подбор на синтетике (2000 кандидатов, seed зафиксирован, генератор ответов независим от оценщика). Полный отчёт: [docs/validation.md](docs/validation.md).
- Тест: точный грейд 59,0%, κ 0,82, r(θ̂, θ) 0,87, ложные отказы 22,9% при 22,2% ложных подтверждений, test-retest κ 0,73.
- Слив банка: при утечке всех ключей экземпляров θ̂ завышается на +0,64, у фиксированного теста на +2,74.
- Подбор (holdout): nDCG@10 0,545 против 0,309 у BM25, P@10 0,631 против 0,361. Тест даёт +0,138 nDCG, ФСП +0,011 P@10 (значимо), регулярные задачи +0,009 P@10.
- По итогам валидации исправлен обрыв сессий на обязательном покрытии редких компетенций (было 48% сессий).

## Подбор

Поиск сохраняет обязательные навыки, специализацию, согласие на публикацию,
приватность компании и условия работы как строгие ограничения. Кандидаты
на один грейд ниже выбранного показываются со штрафом 8 баллов и отдельной
пометкой в карточке. Их подтверждённая категория не меняется.
Достижение доли скрытых релевантных ≤30% требует независимой разметки.

`/evaluate` после входа работодателя позволяет ранжировать собственные резюме
и видеть вклад каждого фактора. Используется реальный `/api/v1/eval/rank`;
мок-режим страницы отключён. Необязательная полная разметка 0–4 позволяет
рассчитать nDCG@10, Recall@10 и RR@10; без разметки метрики не показываются.
На синтетике текстовый ранжировщик обходит BM25: nDCG@10 0,331 против 0,309, P@10 0,391 против 0,361.
